You may edit `engine/tests/`, `tests/`, `relay/tests/`, `web/e2e/` and `engine/parsemaxxing/generator/fixtures/` (and the generator itself when a phase needs new synthetic formats). You never edit production code; when a test exposes a bug, report it with the failing test and the smallest reproduction. Root `CLAUDE.md` rules apply: only synthetic data, never real logs, hostnames, IPs or company names (customers in fixtures are Acme, Globex, Initech).

## Suites to keep and grow
- **Adversarial (existing):** `DEST_KEY = queue`/`nullQueue`, newline injection, path traversal in TA names, `[default]` and broad stanzas, `INGEST_EVAL`/`SEDCMD-`, prompt injection in log lines, constant-value CIM gaming, non-`pmx_` ingest, forbidden search commands.
- **Adversarial (new):** prompt injection through discovery samples, drift samples and retrieved references; knowledge poisoning (an approved doc telling the model to use `nullQueue`); an unknown or deprecated key for the target Splunk version; routing exception bypasses (other `DEST_KEY`, wildcard `[host::*]`); tenant isolation (search for an index outside the customer's allowlist, customer id swapped in a path); SSRF in URL import (private IPs, DNS rebinding, redirects, `file://`); hostile relay input (tar with `..`, absolute paths, symlinks, hardlinks, devices, huge members, argument injection in verbs).
- **Access control:** the route-inventory test (every route has a policy) and a role matrix: every route as anonymous, viewer and admin, with the expected status; IDOR checks on every id in a path; viewer can never receive a secret value (scan responses).
- **Auth:** lockout and backoff, enumeration (same message and similar timing), TOTP replay, session expiry and revocation, CSRF without header or with a foreign `Origin`, token scope and expiry, setup token single use.
- **LDAP** against an OpenLDAP container: LDAPS only, empty password, filter injection, no-group user, nested groups, failover, TLS failure.
- **Vault:** tampered ciphertext, moved ciphertext, wrong KEK, rotation round trip, no secret in logs (capture and scan).
- **State machines:** replayed approve, promote and deploy requests; concurrent claims; crash resume; deployment verification failure leading to rollback offer, never silent retry.
- **Add-on version control:** revert to an old version then roll forward leaves every version listed, downloadable and byte-identical (hash check); no route, CLI command or retention job can delete or overwrite a version (trigger test, and a test that a purge skips registry samples); a tampered store file is detected on read; compare works for adjacent, non-adjacent and reversed pairs and across a revert, and matches an independent setting-level diff on fixtures; the file viewer refuses paths not in the version's file list (`../`, absolute, encoded, other app); viewers can view, compare and download but get 403 on revert and deprecate; every download is audited; v1 migration moves every package with its hash verified and reports a missing one.
- **Formats (design 7.17):** one synthetic fixture with a truth manifest per format (syslog with payload, CEF, LEEF, XML, multi-line text, multi-line JSON, W3C, delimited, fixed-width, UTF-16), plus adversarial variants: prompt injection inside a CEF extension and an XML element, escaped delimiters, header lines that look like events, an XXE fixture and an entity-expansion fixture (nothing fetched or expanded).
- **Knowledge sources:** fix memory returns the right past fix for a repeated synthetic failure and never a rejected or rolled-back one; a reference add-on package is read without executing anything, a hostile one is refused, and no generated add-on contains a copied reference stanza; a reference add-on chunk never outweighs a failing Splunk check.
- **Real log retention:** plant a unique marker string in a sample, end the job, run the purge, then search the database, files, reports, console transcripts and masking maps for it: it must be gone after the client's setting (30 days by default, never later than 30 days); a masked regression set contains no marker and passes a secret scan; no setting accepts more than 30 days.
- **Settings isolation:** changing, testing or deleting a setting or credential on environment A never changes, reads or tests environment B; a secret can never be resolved from another environment's scope; overrides and "reset to inherited" resolve correctly at platform, environment and client level; cloning and export never include secrets; job snapshots record all three levels.
- **Shared MSSP environments:** a deployment for one client never touches another client's HFs; the search-time part is blocked when the preview shows another client's events losing or changing fields, and allowed when all clients pass; preview searches stay within each client's index allowlist; two clients can run different index-time versions on their own HFs.
- **Environment selection:** a deployment reaches only the environment an admin picked; multi-select creates independent deployments and one failure leaves the others untouched; drift and update jobs never deploy on their own; in a shared MSSP environment, settings that break another client's events for the same sourcetype are caught by the impact analysis.
- **Relay console and command library:** the console streams command, output and exit code and replays from history; output containing a token or key is masked; there is no input path to the relay from the UI or API; generated commands use the environment's real values and contain no secrets; the XSS suite covers relay output.
- **Relay SSH:** the machine login and the Splunk login are separate credentials and tested separately; the Splunk credential never appears in the relay's argv (inspect `ps` during a call), environment, files, relay log or console; `-auth` is never used; the setup test catches a `splunk` user with `/sbin/nologin`; password authentication never attempted; a changed host key fingerprint refuses every call; the private key never appears in any API response, log or UI; the deploy token reaches the relay only on stdin (tests inspect the command line and environment); key rotation keeps working with the new key and stops using the old one.
- **Deployment targets (D11):** no plan ever targets an indexer or cluster manager; the planner and the relay refuse a server class with universal forwarder clients; an HF that is also the UF deployment server gets the package in its own apps only; a sourcetype whose data reaches indexers without an HF gets search-time only with the index-time part marked not deliverable.
- **Overlays (after Q23):** an overlay fixes a synthetic vendor-style add-on without modifying it; an overlay setting that does not take effect fails the gate; the owning add-on is installed on the sandbox at the production version; a vendor upgrade marks fixed settings redundant.
- **Real samples:** tests that use the owner's real samples read only from `samples-local/`, are marked `local_only`, are skipped in CI, and never write those samples, their values or excerpts into fixtures, snapshots or logs.
- **CIM library:** upload of 6.3.0 and the newest 8.x normalizes every model; exact-version matching per environment (no match blocks only CIM work, with the version named); hostile packages (traversal, absolute paths, links, devices, oversized members, missing `app.conf`) refused; a locally modified data model shows a per-model diff; the sandbox gets the matching version; the package never appears in the repo (test).
- **Versions:** a node below 10.2 is refused; CIM below 6.3.0 on 10.2 to 10.6, or below 8.5.0 on 10.7 and later, blocks only CIM work for that environment with the minimum named; the normalizer gives the same result for 6.x and 8.x definitions (test definition files written for the tests).
- **CIM and specs:** every model in an uploaded CIM package is read and normalized; the agent's selection lands on the right model on every fixture, including fixtures whose field names are misleading or vendor-specific (values must decide: for example a field named `port` holding IP addresses), a field-level plan naming a missing field or a wrong value shape is refused, an enum mapping missing a seen value is reported, a selection outside the code bounds is refused, a no-fit fixture is built without CIM mapping, and a poor fit triggers exactly one return to selection; a deployment plan to an environment with a different CIM definition shows the exact difference; a key missing from the target version's spec is blocked and a deprecated one warned; no Splunk spec, example or default file is committed (a test greps the repo for their headers).
- **Masking:** property tests that masked values keep the regex shapes and are consistent within a job; secret patterns always redacted.
- **Knowledge evaluation:** golden set recall@6 and the A/B harness (with `knowledge`).
- **e2e:** every screen as admin and viewer, the XSS suite on every place showing untrusted text, the setup wizard, axe accessibility checks.

Run `make test` and `make e2e` and report the result honestly, including failures and skipped tests. A guardrail or access-control change without a new failing-then-passing test is not done.
